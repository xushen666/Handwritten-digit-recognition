# 手写数字识别项目重构设计规格

- 日期：2026-08-25
- 状态：已由项目所有者确认，按 PyQt 桌面端方向修订
- 目标岗位：AI 应用工程师
- 实施时限：一天内完成首个可展示闭环
- 唯一产品入口：Windows PyQt 桌面客户端

## 1. 背景与事实基线

原项目是一个课程小组作业，核心实现由仓库所有者主导完成。现有程序使用 PyTorch 训练 CNN，并通过 PyQt5 提供手写画板。原始归档混合了源码、模型、MNIST 数据、课程报告、IDE 配置和大量构建产物，不适合直接公开维护。

旧训练记录曾出现 99.71% 测试准确率，但训练脚本使用测试集选择最佳模型，课程报告中的部分功能、参数量和性能数字也与源码不一致。公开版本只引用本次可复现训练生成的模型、指标和图表。

## 2. 重构目标

首版只完成一个清晰闭环：

1. 固定配置重新训练，并严格划分训练集、验证集和测试集。
2. 将模型、预处理、空白判断、路径解析和推理封装为共享核心。
3. 重构现有 PyQt 画板，使其直接调用共享核心并可离线识别。
4. 提供模型元数据、准确率、混淆矩阵、训练曲线和 CPU 延迟数据。
5. 提供快速测试、Ruff、GitHub Actions 和 Windows PyInstaller 打包。
6. 提供可信 README、演示截图、简历项目描述和 Release 下载入口。

项目叙事聚焦“AI 桌面应用工程化与模型评测”，不承担后端服务项目的展示职责。

## 3. 明确不做

首版不包含：

- FastAPI、Uvicorn 或任何 HTTP 后端服务；
- Web 页面、前端构建或在线演示；
- Docker 镜像或在线部署；
- 数据库、登录、历史记录、用户纠错或持续训练；
- ONNX、量化、剪枝、蒸馏或 Grad-CAM；
- 多模型切换、复杂可视化或生产级 OCR 声明。

除修复闭环所必需的内容外，不新增功能。

## 4. 仓库结构与职责

```text
Handwritten-digit-recognition/
├─ src/digit_recognizer/
│  ├─ core/          # 唯一模型定义、预处理、路径和 Predictor
│  ├─ training/      # 可复现训练、最终评测和产物生成
│  └─ desktop/       # PyQt 画板、窗口和桌面入口
├─ scripts/          # 训练和文档同步入口
├─ tests/            # 核心、训练、桌面与文档契约测试
├─ models/           # 发布权重和模型元数据
├─ reports/          # 指标、训练曲线和混淆矩阵
├─ packaging/        # Windows PyInstaller 配置
├─ docs/             # 截图、简历文案和设计/实施文档
├─ .github/workflows/
├─ pyproject.toml
├─ README.md
└─ LICENSE
```

模型结构、输入尺寸、归一化参数、空白输入判断和推理逻辑只能在共享核心中定义。训练与桌面端引用同一配置，不复制算法逻辑。

## 5. 数据流

```text
MNIST -> 固定 train/validation 划分 -> 训练 -> 最佳验证权重
                                            |
                                            +-> 最终测试一次
                                            +-> metrics / metadata / PNG

PyQt 画板 -> PIL 图像 -> 共享预处理 -> Predictor -> 数字、置信度、耗时
```

发布模型元数据记录版本、参数量、输入规格、类别、完整训练配置、测试准确率、CPU 延迟和权重 SHA-256。

## 6. 共享推理核心

公共核心必须提供：

- 与既有 CNN 权重兼容的唯一模型定义；
- 28×28 灰度、反色、张量化和统一归一化；
- 对 PIL 与 NumPy 输入的显式校验；
- 透明图像白底合成和空白输入拒绝；
- 权重安全加载、设备选择和开发/打包路径解析；
- 结构化预测结果：数字、置信度和推理耗时。

模型缺失、损坏、格式不匹配和空白输入必须转为明确的领域错误，不向用户展示本机路径或堆栈。

## 7. PyQt 桌面端

桌面端只保留形成闭环所需的交互：

- 280×280 白底手写画板；
- 黑色圆角笔迹；
- “识别”和“清除”按钮；
- 预测数字、置信度和单次推理耗时；
- 空白输入、模型加载和推理失败提示。

画板使用控件自身坐标绘制，避免旧项目的坐标偏移。窗口直接调用共享 `Predictor`，不依赖网络、数据库或后台服务。桌面逻辑使用注入的 Predictor 进行测试，GUI 测试使用 Qt offscreen 模式。

## 8. 训练与评测

- Python 3.11、PyTorch 2.10+ 和 torchvision 0.25+。
- 固定随机种子 42，默认训练 15 轮。
- 从 60,000 个训练样本中固定划分 5,000 个验证样本。
- 训练集使用轻量数据增强；验证集和测试集不增强。
- 只按验证准确率保存最佳权重；测试集不参与选择。
- 最佳权重训练结束后加载，测试集只遍历一次。
- 测试准确率低于 99.0% 时训练命令非零退出。
- checkpoint 先写同目录临时文件，成功后原子发布；异常不得复用旧权重。
- 绘图固定使用无界面 `Agg` 后端，避免桌面 GUI 后端阻塞训练。

必须生成：

- `models/mnist_cnn.pth`
- `models/model_metadata.json`
- `reports/history.json`
- `reports/metrics.json`
- `reports/training_curves.png`
- `reports/confusion_matrix.png`

## 9. 测试、CI 与 Windows 发布

快速测试覆盖：

- 模型参数量和前向输出形状；
- 图像转换、归一化、透明图、非法输入和空白判断；
- 模型路径优先级、安全权重加载和预测返回结构；
- 固定数据划分、最佳 checkpoint 重载、测试集单次遍历；
- 完整模型元数据、SHA-256、指标阈值和无界面绘图；
- PyQt 画板转换、清除、识别成功和错误提示关键路径；
- README 与评测指标一致性。

GitHub Actions 只运行 CPU 快速测试、Ruff 和构建检查，不下载 MNIST、不重新训练。标签 `v*` 触发 Windows onedir PyInstaller 构建，并上传压缩包到 GitHub Release。

首版不使用 Docker。Windows 可执行程序是唯一二进制交付物。

## 10. README、简历与隐私

README 采用英文短简介加中文正文，包含项目截图、架构、桌面端快速启动、训练/测试命令、真实评测表、局限和 Release 下载入口。

简历材料固定为三条：

1. 共享核心与 PyQt 桌面应用重构；
2. 无测试集泄漏的可复现训练和模型评测；
3. 自动化测试、CI 和 Windows 可执行程序交付。

所有量化数字只从生成的 JSON 读取。仓库不得包含原课程报告、成员学号、教师信息、绝对本机路径、IDE 配置、MNIST 原始数据、旧构建目录或凭据。

## 11. 首版验收标准

1. 新环境可安装项目，核心测试和 Ruff 全部通过。
2. 正式训练生成全部六类模型/报告产物。
3. 权重 SHA-256、参数量 585,578 和元数据一致。
4. 最终测试准确率不低于 99.0%，README 与指标 JSON 一致。
5. PyQt 可离线完成绘制、清除、空白拒绝和一次识别。
6. Windows onedir 构建成功，打包程序可启动并加载随包模型。
7. GitHub Actions 配置有效，Release 工作流可生成 ZIP。
8. README、桌面截图和简历文案完整且不泄露隐私。

## 12. 一天内执行顺序

1. 完成共享核心、训练评测代码和快速测试。
2. 正式训练并核验模型、指标和图表。
3. 重构 PyQt 桌面端并进行 offscreen 与人工冒烟测试。
4. 增加 CI、PyInstaller 配置并本地构建 Windows 成品。
5. 用真实指标生成 README 与简历材料，补桌面截图。
6. 完成仓库卫生、全量验证、推送和首版 Release。

如果 GitHub Release 因远程 Runner 问题未能当天完成，源码、测试、本地 Windows 构建、工作流和文档仍必须全部完成，并如实记录未验证项。
